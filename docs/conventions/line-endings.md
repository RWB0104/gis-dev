# Line Ending Conventions

The repository is worked on from both Windows and macOS. To keep Git, editors, Biome, and AI tools in agreement, **every text file uses LF in both the repository and the working tree**.

## Configuration

Three files in the repository root enforce this. Do not rely on personal Git settings.

| File | Setting | Purpose |
|---|---|---|
| `.gitattributes` | `* text=auto eol=lf` | Checks files out with LF on every OS. `eol=lf` takes precedence over `core.autocrlf`. |
| `.editorconfig` | `end_of_line = lf` | Makes editors save with LF. |
| `biome.jsonc` | `formatter.lineEnding: "lf"` | Makes Biome format with LF. (The shared `@itcode-dev/biome-config` already sets this; it is repeated here to make the intent explicit.) |

## Rules

- Never write CRLF into source files, including files generated by AI tools or scripts.
- If a file shows up as modified in Git but its content did not change, the cause is almost always a line-ending mismatch. Fix the line endings instead of committing the noise.
- `core.autocrlf` is irrelevant once `.gitattributes` is present, but on Windows `git config --global core.autocrlf false` avoids confusion with other repositories.

## One-time normalization on an existing checkout

Run this once per machine after pulling the three files above. Commit or stash any local changes first: `git reset --hard` discards uncommitted work.

```bash
git add --renormalize .
git rm --cached -r . && git reset --hard
```

The first command normalizes what is staged; the second rewrites the working tree so that every file is checked out with LF.
